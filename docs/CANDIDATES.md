- **2026-10-21, linux-service - A watcher inside a Landlock sandbox can't read /proc.** A design put "watch the connection, then kill everything the step started, read from /proc" inside the sandboxed child. - **2026-10-21, linux-service - A hand-made remote cleanup gets a review denied.** A reviewer shipped a bundle to the CI VM with `ssh host 'rm -rf ~/dir/repo' && scp ...`; the permission classifier denied it ("Remote Shell Writes"), denied the next harmless local command too, and the review's test run stayed blocked from 07:29 to the verdict at 13:18 UTC (4 h 30 min of it with the session down), until forge CI on the exact tree was accepted as the evidence. - **2026-10-21, linux-service - Forgejo 15.0.9: no job-log API; protected branches always refuse force-push.** Measured on the forge: `actions/runs/N`, `runs/N/jobs`, `actions/jobs/ID/logs` and `tasks/ID/logs` answer 404, and the web log route answers 404 to a token and to basic auth, so an agent sees only the commit status ("Successful in 4m43s"), never the per-step lines. - **2026-10-21, linux-service - A plain git push is a compare-and-swap: a cross-machine lock can be a ref on the forge.** git sends the value it last saw with every ref update, and the server applies it only if the ref still holds it; without `--force`, a push that doesn't fast-forward is refused. So a parentless commit made per run and pushed to a ref (`refs/land/lock`) is a lock that works from any machine: the second push is refused while the first is there, and two that start together can't both create it. Measured on Forgejo 15.0.9: it accepts refs outside `refs/heads`/`refs/tags`, refuses the second push, and runs no CI for them, while a tag push does run `on: [push]` workflows. The same property makes the final `git push <sha>:main` safe: it can't overwrite a main that moved. Release by deleting the ref only while it is still yours; a killed holder leaves it, so print the delete command. Merge queues found for Forgejo (shunt, the forge's "merge when checks succeed") work on pull requests and don't land the tested commit itself. Target: ops-scripting (locks) or agent-team (merging).
