- **2026-10-07, action-rpg - Give a check tool its threat model before the first review.** A review-prep script took six rounds: each adversarial reviewer found one more way a branch could make the tool pass (a skip marker read from the branch, a test tagged slow, a `.globalconfig`, a module shadowing the stdlib beside a checker, a `*.g.cs` file without nullable checks), about 180 M tokens. Target: landing or ops-scripting.
- **2026-10-06, action-rpg - A queue shared by every checkout breaks when one branch's config names something main's doesn't.** The job router keeps one jobs folder for all worktrees. A branch added machines to its routes.json and queued trial jobs for them; every submitter running main's router then probed those older queued jobs' machines by name, hit `KeyError`, and three other agents' jobs were lost. - **2026-10-11, 3d-game - Figures in docs and comments get recomputed from the model, never scaled or fitted.** Moving a camera 24 -> 20 -> 18 m, three review rounds each found figures that had been scaled by the distance ratio or written to fit a screenshot (floor hidden behind a wall, distance to a screen corner, label distance, a slope "1.4 m a metre" wrong at every distance) while the code was right. When a parameter changes, every derived number in docs, comments and tests is recomputed by one script from the geometry, its output kept as evidence, and the reviewer re-runs that script. Target: ground-truth rule 2 or agent-team "Numbers every branch changes".
- **2026-10-21, linux-service - A hand-made remote cleanup gets a review denied.** A reviewer shipped a bundle to the CI VM with `ssh host 'rm -rf ~/dir/repo' && scp ...`; the permission classifier denied it ("Remote Shell Writes"), denied the next harmless local command too, and the review's test run stayed blocked from 07:29 to the verdict at 13:18 UTC (4 h 30 min of it with the session down), until forge CI on the exact tree was accepted as the evidence. Other reviewers ran the same tests on the same VM the same day without a denial. Steps reviewers repeat on a remote box belong in one reviewed script that writes only into a fresh `mktemp -d` and removes only what it made; or run them locally in the project's dev image. Target: landing or ops-scripting.
- **2026-10-21, linux-service - A plain git push is a compare-and-swap: a cross-machine lock can be a ref on the forge.** git sends the value it last saw with every ref update, and the server applies it only if the ref still holds it; without `--force`, a push that doesn't fast-forward is refused. So a parentless commit made per run and pushed to a ref (`refs/land/lock`) is a lock that works from any machine: the second push is refused while the first is there, and two that start together can't both create it. Measured on Forgejo 15.0.9: it accepts refs outside `refs/heads`/`refs/tags`, refuses the second push, and runs no CI for them, while a tag push does run `on: [push]` workflows. The same property makes the final `git push <sha>:main` safe: it can't overwrite a main that moved. Release by deleting the ref only while it is still yours; a killed holder leaves it, so print the delete command. Merge queues found for Forgejo (shunt, the forge's "merge when checks succeed") work on pull requests and don't land the tested commit itself. Target: ops-scripting (locks) or landing.
- **2026-10-21, home-network - A "private ranges to private ranges" inter-VLAN block is IPv4-only.** With IPv6 prefix delegation on, every VLAN has global IPv6 addresses the RFC1918 groups never match, so VLANs in one firewall zone talked freely over IPv6 under both the old and new rule engines. Separate by zone or write rules for both families, and include IPv6 in separation tests. Target: new: network-security.
